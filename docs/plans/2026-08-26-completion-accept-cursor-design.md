# Completion Acceptance and Cursor Authority Design

**Status:** Approved

**Date:** 2026-08-26

## Summary

Accepting any SQL completion candidate ends the current completion session. The
replacement remains a normal revisioned, undoable editor change, but its Changed
effect does not immediately schedule another completion. Programmatic range
replacement also synchronizes the actual modalkit leader cursor so the displayed
cursor and the next insertion position cannot disagree.

## Root Causes

Two independent defects combine in the reported behavior.

First, `CompletionAccept` replaces `SELE` with `SELECT` and produces a normal
`EditorEffect::Changed`. Because `SELECT` ends in an identifier character, the
automatic eligibility predicate schedules completion again and recreates the
same `SELECT` and catalog candidates.

Second, `EditorWorkspace::replace_range` updates `session.position`, then calls
`EditBuffer::set_text`. `set_text` resets modalkit's leader cursor. UI rendering
uses the shadow `session.position`, so it displays `SELECT|`; the next key uses
the real leader at column zero and produces ` SELECT`.

## Completion Session Lifecycle

Accepting every candidate type ends the active completion session:

- keyword;
- schema;
- table or view;
- column;
- function or procedure.

The flow is:

```text
take popup
replace selected range
record revision and undo
synchronize real leader
drain editor effects without completion refresh
leave popup closed
```

The next real user edit uses the ordinary completion eligibility rules. A space
keeps the popup closed; a later identifier character or qualifier dot may trigger
completion again.

No persisted or cross-event `just_accepted_completion` flag is added.

## Effect Handling

Editor effect application gains a local policy:

```rust
enum EditorEffectPolicy {
    Normal,
    SuppressCompletionRefresh,
}
```

Normal editing uses `Normal`. `accept_completion` uses
`SuppressCompletionRefresh` for the effects generated by that replacement.

Suppression applies only to `complete_now` and `ScheduleCompletion`. The Changed
effect still invalidates execution drafts, participates in workspace persistence,
and retains revision and history semantics.

## Cursor Authority

Programmatic range replacement computes the desired post-edit position, replaces
text, and writes the same position to the real modalkit leader:

```text
next text
desired EditorPosition
buffer.set_text(next)
buffer.set_leader(group_id, Cursor::new(line, column))
session.position = desired projection
```

Render snapshots and current-scope resolution should derive cursor coordinates
from `buffer.get_leader(group_id)` wherever practical. `session.position` is a
compatibility projection, not an independent authority.

Undo, redo, formatting, substitution, search, and restore paths must preserve the
same invariant whenever they use whole-buffer replacement.

## Expected Behavior

```text
SELE
accept SELECT
SELECT|
popup none
type space
SELECT |
```

```text
tools.sys
accept sys_config
tools."sys_config"|
popup none
type space
tools."sys_config" |
```

Completion acceptance remains undoable:

```text
SELE -> SELECT -> Esc -> u -> SELE
```

## Tests

Full App-path tests assert popup state, displayed cursor, text after continued
typing, and undo behavior for keyword and quoted catalog candidates.

Editor tests assert that `replace_range(..., EndOfInsertion)` updates both
`position()` and `render_snapshot.cursor`, and that the next Insert key writes at
that exact offset.

Existing Vim, completion boundary, popup positioning, target, transaction, and
workspace tests remain green.

## Acceptance Criteria

1. Accepting any candidate closes the popup without immediate reopening.
2. Typing after acceptance inserts at the displayed cursor.
3. `SELECT|` plus space becomes `SELECT |`, never ` SELECT`.
4. Quoted catalog candidates have the same behavior.
5. Completion acceptance remains one undoable change.
6. UI cursor and modalkit leader are consistent after all programmatic edits.
